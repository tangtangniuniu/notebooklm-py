### 幻灯片 11：是什么（代表架构拆解）
**内容**：
- **单 Agent + Tools 模式（以 HolmesGPT / Bits AI Investigate 为代表）**：
  - *架构*：一个模型充当“大脑”，搭配少量 K8s 诊断插件或日志查询接口 [13, 20]。
  - *局限*：极易发生工具调用失败传播（Tool Failure Propagation）；长上下文幻觉（产生不存在的服务名如“ts-payment-service”） [52]。
- **编排式 Multi-Agent（以 Opsworker.ai / Slack Security 为代表）**：
  - *架构*：切分为 8+ 个专门 Agent：Orchestrator（总调度）、Topology Mapper（拓扑映射）、Signal Correlator（信号关联）、Critic（复核专家）等 [50, 51]。
  - *局限*：状态保持困难，多个 Agent 在上下文接力时容易丢失关键 Token（Memory Lapse） [60]。
- **自治闭环式（以华为 AEI@DC 为代表）**：
  - *架构*：集成“高清数字孪生环境”+“多域 Agent（计算/存储/网络）”+“传统管控单元” [61, 62]。利用数字孪生进行“网络时光机”沙盒验证，确认无误后再下发执行。
  - *局限*：老旧系统集成成本极高，极度依赖原厂硬件的接口规范 [57, 63]。

【关注点】
1. 复杂的 Multi-Agent 系统在真实临床/重保场景中经常出现“责任推诿（Handover Failures）”，必须设立强干预信号 [60]。
2. 架构设计已放弃让大模型“自由发挥”，而是转为严格的“思维递归（Recursion-of-Thought）”和表单输出填充 [33, 64]。

### 幻灯片 14：关键技术列表
**内容**：
- **GRPO（分组相对策略优化）与 DeepSeekMath**：不再依赖庞大的判别模型，直接从多路径推理的相对质量给出奖励，解决了逻辑推演过程的强化学习成本 [60, 69]。
- **MCP（Model Context Protocol）工具标准**：Red Hat / Anthropic 推动的行业标准网关，确保 Agent 在不直接接触密码硬编码的前提下安全获取云日志与监控面板权限 [21, 22]。
- **FTI（故障树诱导生成）**：结合传统的故障树分析（FTA）经验知识体系，让模型在面对 Unknown 故障时主动进行“排除法剪枝（Reverse Deduction）”推理 [54, 70]。
- **逻辑链引导蒸馏（CoL Distillation）**：将 GPT-4 / Claude 3.5 产生的优秀 RCA 推理路径提取压缩到 7B-32B 规模的私有化部署小模型中，大幅降低侧端延迟 [71]。
- **Recursion-of-Thought（递归思维链）**：改变线性 CoT 模式，系统在调用 Trace 后如发现线索中断，可动态触发 fallback 动作，如自动补打一段 Metric 查询并重构前置诊断结论 [64, 72]。
