幻灯片 11：诊断方案 1 —— ReAct 与工具增强智能体（Tool-Augmented Agent）
内容
：
实现原理
：基于“思考-行动-观察”（Thought-Action-Observation）循环。模型不再一次性生成所有答案，而是输出当前思考，调用外部工具（如执行 Shell 脚本或 SQL 查询），并根据工具返回的回显（Observation）决定下一步动作 [59, 60]。
代表架构 / 产品
：
SADE（Symptom-Aware Diagnostic Escalation）框架
：2026 提出的故障排除模型。依据基础设施 -> 控制面 -> 主机 -> 服务的逐层排查原则，通过 LLM 动态调用 
nftables
、
vtysh
 等探针工具收集证据 [43, 61]。
Cisco Deep Research AI Agents
：思科将诊断分解为假设生成、假设测试与修复草案生成，模型通过不断证伪来逼近根因 [62, 63]。
当前局限
：在极端复杂的长周期排障中，模型容易在工具调用的循环中“迷失方向”并耗尽 Token 预算 [64]。
【关注点】
SADE 框架通过结合专家技能文档（Skill.md 作为 In-context 约束），使大模型在无需重新训练微调的情况下，能对任何异构网络拓扑进行动态探查 [65]。

幻灯片 12：诊断方案 2 —— 知识图谱增强推理（KG-Enhanced Reasoning）
内容
：
实现原理
：将静态的运维机理知识（设备依赖、协议层级、告警传递规则）结构化为实体-关系图谱。大模型在推理前，先从图谱中抽取相关子图作为背景约束，将黑盒神经网络转化为神经符号系统（Neuro-symbolic AI），强制模型遵循物理现实逻辑 [66]。
代表架构 / 产品
：
FDRKG-LLM
（西安交大 2025/2026 研究）：将故障诊断推理与知识图谱融合的管线模型，超越了普通 RAG 的表现，专治模型面对设备故障时的幻觉现象 [67, 68]。
中兴/联通图谱诊断实践
：将告警、性能异常建模为节点，通过语义相似度算法挖掘隐性关联，辅助根因定位准确率达到 95% 以上 [22, 69]。
当前局限
：多厂商设备异构数据的对齐、清洗与高质量图谱的持续更新成本极其高昂 [70]。
【有趣发现】
纯 RAG 只能检索出历史相似文本，而结合知识图谱的大模型具备了“发现隐形依赖（Hidden Dependency）”的演绎推理能力，能定位配置管理数据库（CMDB）中漏记的防火墙阻断节点 [71]。

幻灯片 13：诊断方案 3 —— 递归思维链（RoT）与 GRPO 强化微调
内容
：
实现原理
：抛弃线性的思维链（CoT），采用递归思维（Recursion-of-Thought, RoT）。模型在探索发现死胡同时，能主动回溯到上游决策点并改变工具调用策略。同时，利用 GRPO（分组相对策略优化）算法，在不需要庞大判别模型的情况下，对轻量级小模型（SLMs）进行推理策略强化学习 [72, 73]。
代表架构 / 产品
：
ThinkFL 模型
：采用渐进式多阶段 GRPO 微调框架，结合“多因子故障定位评分器”与 RoT 动作模块。针对微服务系统，将端到端定位延迟从数分钟压缩至几秒钟 [72]。
DeepSeek V4/R1 架构底座
：通过 RL（强化学习）重点优化后训练阶段，使得几十亿参数的小模型在故障逻辑推演上匹敌甚至超越千亿参数通用模型 [3, 74]。
当前局限
：模型极度依赖底层探针提供的高保真时序数据；如果特征工程（如 eBPF 采集）存在数据乱序，算法将产生级联误判。
【关注点】
业界抛弃了死板的“步骤 1-2-3”指令链，赋予模型主动试错与回退的权力，这是降低 MTTR 的底层算法革新 [75]。

幻灯片 14：诊断方案 4 —— 网络数字孪生 (NDT) 与故障树诱导 (FTI)
内容
：
实现原理
：构建与物理世界 1:1 映射的高清虚拟网络（Network Digital Twin）。当大模型推导出修复指令（如切断某 OSPF 邻居）时，必须先在孪生沙盒中进行“What-If”模拟测试；测试验证无次生灾害后，方可通过自动化网关向物理设备下发 [5, 55, 76]。
代表架构 / 产品
：
Aether 验证框架
：利用 Agentic AI 和数字孪生，在 LLM 上下文中直接嵌入设备拓扑状态，通过 Batfish 等分析工具执行路由可达性测试，再由执行器接管操作 [77, 78]。
中兴智能运维孪生
：基于全域立体智能监控，结合场景化应急恢复联动数字孪生，实现“先验后行”的无风险配置 [51]。
当前局限
：对计算资源消耗极大，数字空间与物理环境的微秒级状态同步（数据新鲜度）是技术瓶颈 [44, 79]。
【关注点】
面对不可逆的物理变更（如端口 Shutdown），NDT 是解决大规模“AI Oops（系统瘫痪）”事件、满足欧盟安全法案审计要求的最后防线 [80, 81]。

幻灯片 15：诊断方案 5 —— 多智能体协同（Multi-Agent Orchestration）
内容
：
实现原理
：针对云网融合带来的跨域复杂性，废弃单中心大模型，采用编排式框架。将任务拆分给具有独立职能的多个 Agent（如：Director、Expert、Critic），通过 A2A（智能体间通信协议）协商参数，完成诊断接力 [39, 45]。
代表架构 / 产品
：
中国移动“多级多智能体故障自愈” Catalyst
：底层为基于 10 万条故障语料微调的诊断 Agent，中层为跨域调度 Agent 与修复脚本生成 Agent 交互，实现端到端传输网告警自处理 [39, 82]。
mABC 框架（区块链启发）
：引入进程调度、数据侦探、故障映射和解决方案工程师等不同角色 Agent，通过投票机制达成对微服务 Trace 断点的一致性诊断 [75, 83]。
当前局限
：在深层微服务通信中，多个 Agent 频繁交换上下文容易引发严重的 Token 冗余膨胀，推升运算成本 [53, 84]。
【有趣发现】
“多智能体谈判”正在取代传统的跨部门工单流转。网络域 Agent 发现拥塞后，可以直接与存储域 Agent 通过协议商定 QoS 降级代价，全程耗时不到 1 秒 [85, 86]。
